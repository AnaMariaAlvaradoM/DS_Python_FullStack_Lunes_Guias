Cómo funciona una página web

4.1 · Qué pasa cuando escribes una dirección

Cuando escribes pulsofit.co en el navegador, pasa algo que ya conoces del backend: el navegador hace una petición HTTP y un servidor responde.

La diferencia: tu FastAPI respondía JSON. Un servidor web responde archivos que el navegador sabe leer.

4.3 · Navegador

  • Técnica: programa que pide archivos por HTTP, los interpreta y los dibuja en pantalla (Chrome, Edge, Firefox, Safari).
  • En la vida real: es como un traductor: recibe instrucciones escritas y las convierte en algo que tú ves y tocas.

4.4 · Las tres capas

4.5 · HTML · la estructura

  • Técnica: lenguaje de marcado que describe qué hay en la página y qué papel cumple cada cosa: un título, un párrafo, un botón.
  • En PulsoFit: "aquí va el nombre del gimnasio, aquí la lista de clases, aquí el botón Reservar".

4.6 · CSS · la presentación

  • Técnica: lenguaje de estilos que describe cómo se ve cada elemento: color, tamaño, espacio, posición.
  • En PulsoFit: "las tarjetas son blancas, con bordes redondeados y una al lado de la otra".

4.7 · JavaScript · el comportamiento

  • Técnica: lenguaje de programación que corre dentro del navegador y reacciona a lo que hace la persona: modifica la página, responde a clics, pide datos a una API.
  • En PulsoFit: "cuando alguien toque Reservar, descuenta un cupo".

4.8 · La analogía: el propio gimnasio

Piensa en la sede de PulsoFit:

  • son las paredes y los salones: el salón de spinning, la recepción, los casilleros.
  • es la pintura, la iluminación y cómo se acomodan las máquinas.
  • es el torniquete que abre cuando pones tu huella: reacciona a lo que haces.

Un gimnasio sin paredes no existe; sin pintura funciona pero se ve mal; sin torniquete, nadie controla el acceso.

Para pensar

Valeria pide que una clase sin cupos no se pueda reservar. ¿Cuál de las tres capas se encarga de eso?

Comprobar

JavaScript. El botón existe gracias a HTML y se ve gris gracias a CSS, pero decidir que no se puede reservar porque los cupos llegaron a cero es comportamiento: una regla que se evalúa mientras la página está abierta.

4.9 · Por qué React necesita esto

React no es un cuarto lenguaje. Es una librería de JavaScript que genera HTML y que se estiliza con CSS.

En la Clase 1 vas a ver… …y en realidad es
Un componente de React Una función de JavaScript
JSX (<h3>{clase.nombre}</h3>) HTML escrito dentro de JavaScript
Clases de Tailwind (p-4 rounded-lg) Atajos de CSS
useState Datos que, al cambiar, vuelven a pintar la pantalla

6.1 · La pieza básica: el elemento

6.2 · Qué es un elemento

  • Técnica: un elemento HTML es una pieza de la página marcada con una etiqueta de apertura, un contenido y una etiqueta de cierre.
  • En la vida real: es como las etiquetas de una caja de mudanza: "Cocina", "Libros". No cambian lo que hay dentro, pero dicen qué es.

6.3 · Anatomía de un elemento

Referencia
 etiqueta de apertura        contenido         etiqueta de cierre
        │                        │                     │
   <button class="btn">      Reservar            </button>
            └─────┬─────┘
              atributo: información extra sobre el elemento
  • Etiqueta: el nombre entre < y >. Dice qué tipo de cosa es.
  • Cierre: la misma etiqueta con /. Dice dónde termina.
  • Atributo: un dato extra dentro de la etiqueta de apertura, con la forma nombre="valor".

6.4 · Los elementos se meten unos dentro de otros

Un elemento puede contener otros elementos. Eso forma un árbol: la página entera es un elemento que contiene la cabecera, que contiene el título, y así.

Ese árbol va a ser clave en el Momento 7: JavaScript lo recorre para cambiar la página.

  1. L1<!DOCTYPE html>

    🟨 Lenguaje · Le avisa al navegador que el archivo usa HTML moderno. No es una etiqueta y no se cierra; sin ella, el navegador entra en un modo antiguo de compatibilidad.

  2. L2<html lang="es">

    🟨 Lenguaje · html abre el elemento raíz: todo lo demás va dentro. El atributo lang="es" dice que el contenido está en español; lo usan los lectores de pantalla para pronunciar bien y el navegador para ofrecer traducción.

  3. L3<head>

    🟨 Lenguaje · Abre la cabeza del documento: información sobre la página que no se dibuja en ella.

  4. L4<meta charset="UTF-8">

    🟨 Lenguaje · Dice con qué codificación están escritos los caracteres. Con UTF-8 las tildes, la ñ y el punto medio · se ven bien. meta no tiene cierre porque no tiene contenido.

  5. L5<meta name="viewport" …>

    🟩 Plataforma · Le pide al navegador del celular que use el ancho real de la pantalla (width=device-width) sin zoom inicial (initial-scale=1.0). Valeria quiere que la gente reserve desde el celular.

  6. L6<title>…</title>

    🟨 Lenguaje · El texto de la pestaña del navegador y el que aparece en los resultados de búsqueda. 🟪 El texto es decisión nuestra.

  7. L7</head>

    🟨 Lenguaje · Cierra la cabeza.

  8. L8<body>

    🟨 Lenguaje · Abre el cuerpo: todo lo que va aquí sí se dibuja en pantalla.

  9. L9<h1>PulsoFit</h1>

    🟨 Lenguaje · h1 es el título principal de la página; solo debe haber uno. 🟪 El texto es el nombre del gimnasio.

  10. L10-11</body> y </html>

    🟨 Lenguaje · Cierran el cuerpo y el documento, en orden inverso al que se abrieron.

7.2 · Levanta el servidor

Abre una terminal en Cursor: menú Terminal → New Terminal. La terminal abre en la carpeta pulsofit; verifícalo con pwd (o cd en Windows).

Ejecuta este comando desde la carpeta pulsofit:

Terminal

7.3 · Qué hace ese comando

  • python -m http.server le pide a Python que ejecute su servidor web incluido.
  • 5500 es el puerto. No usamos el 8000 porque es el que usa uvicorn por defecto: así puedes tener tu FastAPI y esta página abiertas al mismo tiempo.
  • En Mac o Linux el comando puede ser python3 en lugar de python.

9.1 · La pieza básica: la regla CSS

9.2 · Qué es una regla

  • Técnica: una regla CSS tiene un selector (a quién le aplico) y un bloque de declaraciones propiedad: valor; (qué le cambio).
  • En la vida real: es como una orden en el gimnasio: "a todos los entrenadores → camiseta negra, gorra roja". Primero a quién, después qué.

9.4 · Tres formas de elegir a quién

Selector Se escribe Elige Ejemplo hoy

9.5 · Para qué sirve el atributo class

Una clase es un nombre que tú le pones a un elemento para poder elegirlo desde CSS. Varios elementos pueden compartir la misma clase: las dos tarjetas se llamarán tarjeta.

En HTML se escribe class="tarjeta"; en CSS se elige con punto: .tarjeta.

10.3 · El modelo de caja

10.4 · Qué es

  • Técnica: el navegador dibuja cada elemento como una caja con cuatro capas: contenido, relleno (padding), borde (border) y margen (margin).
  • En la vida real: un cuadro colgado en la pared: la foto es el contenido, el paspartú blanco es el padding, el marco es el border y el espacio hasta el siguiente cuadro es el margin.

13.2 · El DOM: el puente entre JavaScript y la pantalla

13.3 · Qué es

  • Técnica: el DOM (Document Object Model) es el árbol de objetos que el navegador construye a partir del HTML. Cada elemento es un objeto que JavaScript puede buscar, leer y modificar.
  • En la vida real: el HTML es el plano del gimnasio en papel; el DOM es el gimnasio construido. JavaScript no edita el plano: entra al gimnasio y mueve las cosas.

import { clases } from "./datos.js";

const lista = document.querySelector("#lista-clases");
const contador = document.querySelector("#contador");
let misReservas = 0;

function renderizar() {
  lista.innerHTML = clases
    .map(
      (clase) => `
        <article class="tarjeta">
          <h3>${clase.nombre}</h3>
          <p>Entrena: ${clase.entrenador}</p>
          <p>Hora: ${clase.hora}</p>
          <p>Cupos: ${clase.cupos}</p>
          <button class="btn-reservar" data-id="${clase.id}" ${clase.cupos === 0 ? "disabled" : ""}>
            ${clase.cupos === 0 ? "Agotada" : "Reservar"}
          </button>
        </article>
      `
    )
    .join("");

  contador.textContent = misReservas;

  document.querySelectorAll(".btn-reservar").forEach((boton) => {
    boton.addEventListener("click", () => reservar(Number(boton.dataset.id)));
  });
}

function reservar(id) {
  const clase = clases.find((c) => c.id === id);
  if (clase.cupos === 0) return;
  clase.cupos -= 1;
  misReservas += 1;
  renderizar();
}

Por qué existe React

24.1 · Lo que te costó hoy

Para que PulsoFit funcionara tuviste que encargarte, a mano, de tres cosas:

  1. Construir el HTML como texto dentro de JavaScript.
  2. Acordarte de llamar a renderizar() cada vez que cambia un dato.
  3. Acordarte de actualizar cada pedazo de pantalla (el contador) y volver a conectar los botones.

Si olvidas una sola, la pantalla miente. Lo viste con el contador en cero.

24.2 · La idea de React, en una frase

La pantalla es una función de los datos. Tú describes cómo se ve la página para unos datos dados; cuando los datos cambian, React vuelve a pintar lo necesario por ti.

Errores frecuentes y cómo leerlos

28.1 · La consola menciona CORS policy y origin 'null'

  • Cómo se lee: el navegador bloqueó la carga de app.js porque la página no llegó desde un servidor.
  • Causa: abriste index.html con doble clic (la barra dice file:///).
  • Solución: levanta python -m http.server 5500 en la carpeta pulsofit y abre http://localhost:5500.

28.2 · La página se ve sin estilos

  • Cómo se lee: en la terminal de Python aparece "GET /estilos.css HTTP/1.1" 404: el archivo no se encontró.
  • Causa: el href del link y el nombre del archivo no coinciden, o el archivo está en otra carpeta.
  • Solución: revisa letra por letra y que los dos archivos estén en pulsofit.

28.3 · TypeError: Cannot set properties of null (setting 'innerHTML')

  • Cómo se lee: intentaste escribir innerHTML en algo que vale null, es decir, que no existe.
  • Causa: querySelector no encontró el elemento; el id en el HTML y el de app.js son distintos.
  • Solución: compara id="lista-clases" con "#lista-clases": mismo nombre y el # solo en JavaScript.

28.4 · SyntaxError: … does not provide an export named 'clases'

  • Cómo se lee: app.js pidió clases y datos.js no lo exporta con ese nombre.
  • Causa: falta export en datos.js o el nombre no coincide (Clases ≠ clases).
  • Solución: export const clases en datos.js e import { clases } en app.js.

28.5 · Failed to resolve module specifier "datos.js"

  • Cómo se lee: el navegador no supo dónde buscar el archivo importado.
  • Causa: la ruta del import no empieza por ./.
  • Solución: from "./datos.js".

28.6 · Aparecen comas entre las tarjetas

  • Cómo se lee: no hay error en consola; la página muestra , sueltas.
  • Causa: falta .join("") después del map.
  • Solución: agrégalo al final de la cadena.

28.7 · Reservar funciona una vez y después los botones no responden

  • Cómo se lee: no hay error en consola; los botones nuevos simplemente no escuchan.
  • Causa: el forEach con addEventListener quedó fuera de renderizar, y cada pintura crea botones nuevos sin listener.
  • Solución: el forEach va dentro de renderizar, después de innerHTML.

28.8 · La terminal dice Address already in use o WinError 10048

  • Cómo se lee: el puerto 5500 ya está ocupado por otro programa (o por otro servidor que dejaste abierto).
  • Solución: cierra la otra terminal con Ctrl+C o usa otro puerto: python -m http.server 5501.
