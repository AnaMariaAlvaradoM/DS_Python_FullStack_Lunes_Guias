Navegación · concepto

La dirección decide qué componente se pinta

3.1 · Para qué existe

En un sitio hecho solo con HTML, cada pantalla es un archivo distinto: inicio.html, clases.html. Al hacer clic en un enlace, el navegador pide el archivo nuevo al servidor y recarga toda la página: se pierde lo que estaba en memoria y la pantalla parpadea.

Una aplicación de React es una sola página (index.html) que React va pintando. Si todo vive en esa única dirección, no puedes guardar una pantalla en favoritos, compartirla ni usar el botón Atrás del navegador. Lo que falta es que la dirección del navegador decida qué componente se pinta, sin recargar.

3.2 · Qué es

Definición técnica

Enrutamiento del lado del cliente

Es la técnica por la cual la aplicación lee la URL del navegador, la compara con una tabla de rutas y pinta el componente que corresponde; al navegar, cambia la URL con la API de historial del navegador sin pedir una página nueva al servidor. React Router es la librería que lo implementa en React: BrowserRouter escucha la URL, Routes y Route forman la tabla, Link navega y useParams lee las partes variables de la dirección.

Explicación sencilla

Escribes una tabla que dice “si la dirección es esta, muestra este componente”. React Router mira la dirección y pinta la fila que coincide. Cuando haces clic en un enlace, cambia la dirección y vuelve a mirar la tabla, sin recargar.

En la vida real

El directorio de un centro comercial. Cada local tiene un número (Local 214); con el número llegas directo, y le puedes decir a alguien “nos vemos en el 214” sin explicarle todo el camino.

3.3 · Cómo reconocerlo

Hazte esta pregunta: ¿alguien querría llegar directo a esta pantalla, guardarla o compartirla? Si la respuesta es sí, esa pantalla necesita su propia ruta. Y si la pantalla es “la misma para muchos elementos” (un libro, un producto, un pedido), la ruta lleva un segmento dinámico con el identificador.

Navegación · límites

Una ruta es para un lugar

7.1 · Cuándo no usarlo

Una ruta es para un lugar: algo que se guarda en favoritos, se comparte o se visita con Atrás. Lo que cambia dentro de una pantalla (abrir un menú, mostrar un mensaje, pasar de un paso a otro en un formulario corto) es estado, no ruta. Si lo vuelves ruta, el botón Atrás empieza a “deshacer” clics pequeños y la persona se pierde.

Tampoco hace falta React Router en una página que de verdad tiene una sola pantalla (una calculadora, un formulario de contacto): sumarías una librería sin necesidad.

API y Axios · concepto

Los datos llegan después de la primera pintada

8.1 · Para qué existe

Hasta hoy, los datos de la pantalla estaban escritos en el código: un arreglo dentro de un archivo .js. Cada persona que abre la página recibe su propia copia y la cambia en su propio navegador. Nadie más se entera.

Cuando los datos tienen que ser los mismos para todos (cupos, saldos, inventario), viven en un servidor, y la pantalla los pide por la red. La respuesta tarda y llega después de que la pantalla ya se dibujó.

8.2 · Qué es

Definición técnica

API HTTP + Axios + useEffect

Una API HTTP es un conjunto de direcciones de un servidor que responden datos según el método. Axios hace peticiones y devuelve una promesa. Con await se espera sin bloquear la página. En React, la petición que debe hacerse cuando un componente aparece se escribe en useEffect; la respuesta se guarda con la función set…, y eso provoca una nueva pintada.

Explicación sencilla

El componente se dibuja primero con una lista vacía. Después, useEffect le pide los datos al servidor con Axios. Cuando llegan, los guardas en el estado y React vuelve a dibujar.

En la vida real

Un restaurante. El mesero te sienta y pone la mesa vacía; después lleva el pedido a la cocina; cuando está listo, lo trae y tu mesa cambia.

import { useEffect, useState } from "react";
import { createRoot } from "react-dom/client";
import axios from "axios";

function Frutas() {
  const [frutas, setFrutas] = useState([]);

  useEffect(() => {
    async function cargar() {
      const respuesta = await axios.get("/ejemplos/api/frutas.json");
      setFrutas(respuesta.data);
    }
    cargar();
  }, []);

  return (
    <ul>
      {frutas.map((fruta) => (
        <li key={fruta.id}>
          {fruta.nombre}: ${fruta.precio}
        </li>
      ))}
    </ul>
  );
}

API y Axios · límites

useEffect no es “el lugar del código asíncrono”

13.1 · Cuándo no usarlo

Reservar es la respuesta a una acción (el clic en “Confirmar”), así que va en la función del evento. useEffect es para lo que debe pasar porque la pantalla apareció o porque una dependencia cambió, no por un clic.

Lo que se puede calcular con datos que ya tienes (un total, una lista filtrada) no necesita efecto ni petición: se calcula al pintar.

13.4 · Conexión

PulsoFit ya cumple lo principal: todos ven los mismos cupos y el servidor no deja pasar a dos personas por uno. Pero la pantalla todavía calla: mientras carga muestra cosas a medias, con el servidor apagado se queda vacía y Camilo no se entera de por qué no pudo reservar.

Para pensar

En una app de banco, “Mis movimientos” muestra los de la cuenta de la dirección. Un botón “Transferir” envía dinero. ¿Qué va en useEffect, con qué dependencias, y qué va en la función del botón?

Ver respuesta

Pedir movimientos va en useEffect con [numeroCuenta]; transferir va en el evento del botón.

La primera acción ocurre al aparecer o cambiar la cuenta. La segunda la provoca una persona; ponerla en un efecto podría enviar dinero cada vez que la pantalla se pinta.

Carga y error · concepto

La pantalla siempre dice qué está pasando

14.1 · Para qué existe

Una petición por la red tiene tres finales posibles: todavía no responde, respondió con datos o falló. Si la pantalla solo sabe pintar los datos, en los otros casos muestra algo a medias o nada.

14.2 · Qué es

Definición técnica

Estados de carga y error

Son valores en el estado que representan en qué punto está una operación asíncrona. El componente usa renderizado condicional: un indicador mientras los datos son null, un mensaje si error tiene texto y los datos cuando llegan. try/catch atrapa el error alrededor de await.

Explicación sencilla

Mientras espera, dice “Cargando…”. Si algo sale mal, dice qué pasó. Si todo sale bien, muestra los datos.

En la vida real

El tablero de vuelos: Programado, Abordando, Retrasado o Cancelado. Aunque la noticia sea mala, el pasajero sabe qué hacer.

import { useEffect, useState } from "react";
import { Link, useNavigate, useParams } from "react-router";
import FormularioReserva from "../components/FormularioReserva.jsx";
import { obtenerClase } from "../services/clasesService.js";
import { crearReserva } from "../services/reservasService.js";

function DetalleClase() {
  const { id } = useParams();
  const navigate = useNavigate();
  const [clase, setClase] = useState(null);
  const [error, setError] = useState("");
  const [errorReserva, setErrorReserva] = useState("");

  useEffect(() => {
    async function cargar() {
      try {
        const datos = await obtenerClase(id);
        setClase(datos);
      } catch (falla) {
        if (falla.response?.status === 404) {
          setError("Esa clase no existe.");
        } else {
          setError("No pudimos cargar la clase. Revisa tu conexión e intenta de nuevo.");
        }
      }
    }
    cargar();
  }, [id]);

  async function confirmar(datos) {
    try {
      await crearReserva({ clase_id: clase.id, ...datos });
      navigate("/mis-reservas");
    } catch (falla) {
      if (falla.response?.status === 409) {
        setErrorReserva("Alguien tomó el último cupo antes que tú. Elige otra clase.");
      } else {
        setErrorReserva("No pudimos guardar tu reserva. Intenta de nuevo en un momento.");
      }
    }
  }

  if (error) {
    return <p className="font-bold text-red-600">{error}</p>;
  }

  if (clase === null) {
    return <p className="text-slate-600">Cargando clase…</p>;
  }

  return (
    <section className="max-w-xl">
      <Link to="/clases" className="text-sm font-bold text-orange-700 underline">
        ← Todas las clases
      </Link>
      <h2 className="mt-3 text-2xl font-bold">{clase.nombre}</h2>
      <p>Entrena: {clase.entrenador}</p>
      <p>Hora: {clase.hora}</p>
      <p className="mb-6">Cupos: {clase.cupos}</p>
      {errorReserva ? (
        <p className="font-bold text-red-600">{errorReserva}</p>
      ) : (
        <FormularioReserva clase={clase} onConfirmar={confirmar} />
      )}
    </section>
  );
}

export default DetalleClase;

18.4 · Errores frecuentes

Leer antes de tiempo

Cannot read properties of null: revisa la carga antes de leer los datos.

Carga antes que error

Un fallo queda atrapado en “Cargando…” para siempre.

Sin try/catch

El error escapa como Uncaught (in promise).

Sin encadenamiento opcional

falla.response no existe cuando nadie respondió.

Equipo de desarrollo

  1. Cada pantalla compartible necesita su dirección. Una tabla decide qué componente se pinta y un segmento dinámico sirve a muchos elementos.
  2. Los datos compartidos viven en un servidor y llegan después de la primera pintada. Se piden en useEffect a través de un servicio; lo que provoca un clic va en el evento.
